🧭 WebMCP, MCP e a Web agêntica

Construa o modelo mental que separa automação visual, APIs, MCP e ferramentas expostas diretamente pela página.

0 de 60%
O que é:

Automação visual interpreta pixels e DOM; uma tool expõe intenção, parâmetros e resposta em um contrato explícito.

Por que aprender:

A estrutura reduz ambiguidade e torna a execução observável sem eliminar a interface humana.

Conceitos-chave:

screenshots são frágeis · DOM muda com o layout · tools têm contrato · UI continua visível

O que é:

API tradicional é um contrato de rede; MCP padroniza a conversa entre um host e servidores de contexto; WebMCP expõe ferramentas ligadas ao estado da página.

Por que aprender:

A fronteira correta evita tratar WebMCP como substituto universal de backend ou de MCP.

Conceitos-chave:

API serve aplicações · MCP conecta hosts · WebMCP vive na página · composição é válida

O que é:

Ferramentas WebMCP acompanham o documento, o usuário autenticado e o estado atual da interface.

Por que aprender:

Registrar só o que pode ser usado naquele momento reduz contexto e chamadas inválidas.

Conceitos-chave:

estado controla oferta · tools podem surgir · tools podem sair · catálogo é contextual

O que é:

O navegador hospeda a tool e a experiência visível; o agente escolhe a ação; o backend continua impondo autorização e regras de negócio.

Por que aprender:

Sem essa separação, uma descrição de tool vira uma falsa barreira de segurança.

Conceitos-chave:

browser orquestra UI · agente propõe ação · backend autoriza · auditoria atravessa camadas

O que é:

A interface deve mostrar o que o agente preencheu e reservar confirmação explícita para efeitos relevantes.

Por que aprender:

O usuário precisa entender a ação antes de autorizar compra, envio, exclusão ou alteração sensível.

Conceitos-chave:

preview antes do efeito · confirmação proporcional · estado visível · cancelamento real

O que é:

Nem toda interação precisa virar tool. Conteúdo editorial, navegação simples e ações sem contrato estável podem continuar apenas como Web semântica.

Por que aprender:

Recusar uma tool ruim preserva o catálogo, a segurança e a capacidade de escolha do agente.

Conceitos-chave:

sem objetivo não há tool · não duplica API à toa · evite ações genéricas · fallback permanece

1.23h

🧪 Ambiente de desenvolvimento

Prepare um ambiente seguro, observável e compatível com a natureza experimental da especificação.

0 de 60%
O que é:

A interface ModelContext é definida para SecureContext; HTTPS e localhost são a base mínima do laboratório.

Por que aprender:

O teste correto separa ausência da API, configuração experimental e falha real do código.

Conceitos-chave:

HTTPS em produção · localhost no laboratório · flag pode variar · origem importa

O que é:

Vite oferece servidor local e módulos ES; Node executa a automação do projeto, não a API WebMCP do documento.

Por que aprender:

A separação permite desenvolver o site em qualquer browser e ativar WebMCP apenas por enhancement progressivo.

Conceitos-chave:

Node para tooling · Vite serve a página · API vive no Document · build não decide suporte

O que é:

Feature detection pergunta pela capacidade real no momento do uso, sem confiar em user-agent ou versão fixa.

Por que aprender:

Como o draft muda, detectar a superfície disponível é mais durável do que codificar uma lista de navegadores.

Conceitos-chave:

teste a propriedade · fallback é funcional · mensagem é honesta · sem sniffing

O que é:

DevTools, console e um inspector local ajudam a observar registro, troca de catálogo, entrada e resultado.

Por que aprender:

Sem evidência, é fácil confundir uma tool bem registrada com uma tool realmente segura e utilizável.

Conceitos-chave:

console estruturado · toolchange observável · inputs de teste · resultado capturado

O que é:

Tipos ajudam o editor e um polyfill pode simular a superfície para testes, mas nenhum deles prova suporte nativo do agente no navegador.

Por que aprender:

Distinguir simulação de implementação impede falsos positivos no relatório de prontidão.

Conceitos-chave:

types não executam · polyfill simula · nativo é diferente · registre o modo

O que é:

A matriz registra navegador, canal, flag, contexto seguro, data e resultado do teste.

Por que aprender:

Uma API experimental exige rastreabilidade; “funciona aqui” não basta para uma equipe ou para produção.

Conceitos-chave:

data do teste · versão e canal · flag documentada · fallback verificado

1.33h

🧾 API declarativa

Transforme formulários semânticos em ferramentas compreensíveis para agentes e ainda controladas pelo usuário.

0 de 60%
O que é:

Os atributos toolname e tooldescription declaram a intenção do formulário sem remover sua semântica HTML.

Por que aprender:

É o caminho de menor esforço para jornadas que já possuem campos, validação e botão de envio.

Conceitos-chave:

form continua HTML · toolname identifica · descrição orienta · progressive enhancement

O que é:

O name do controle vira a propriedade; toolparamdescription explica ao agente o significado e o formato esperado.

Por que aprender:

Labels ajudam pessoas, enquanto descrições precisas reduzem preenchimentos plausíveis porém errados.

Conceitos-chave:

name é chave · label serve pessoas · descrição serve escolha · exemplos esclarecem

O que é:

Tipos de input, required, min, max e opções contribuem para o schema sintetizado pelo navegador.

Por que aprender:

Reutilizar restrições semânticas mantém o formulário manual e a tool alinhados.

Conceitos-chave:

required vira requisito · select limita valores · min/max restringem · algoritmo ainda evolui

O que é:

Sem toolautosubmit, o agente preenche e a página devolve o foco ao usuário para revisão; com o atributo, o envio pode ocorrer automaticamente.

Por que aprender:

A escolha deve seguir o risco e o efeito da ação, não apenas a conveniência do fluxo.

Conceitos-chave:

ausente pede revisão · booleano habilita envio · risco orienta decisão · UI mostra preenchimento

O que é:

Em envio acionado por agente, agentInvoked permite identificar a origem e respondWith entrega uma Promise com o resultado estruturado.

Por que aprender:

O agente recebe um protocolo verificável sem depender de raspar a página após o envio.

Conceitos-chave:

preventDefault primeiro · teste agentInvoked · Promise como resposta · erro é estruturado

O que é:

Estados ativos e eventos toolactivated/toolcanceled permitem destacar o formulário e limpar trabalho pendente.

Por que aprender:

A interface precisa continuar legível quando o agente inicia, o usuário revisa ou a chamada é cancelada.

Conceitos-chave:

estado visual explícito · cancelamento limpa UI · draft pode mudar · fallback não depende disso

1.43h

⚙️ API imperativa

Registre ferramentas JavaScript com schemas, execução assíncrona, cancelamento e resultados estruturados.

0 de 60%
O que é:

document.modelContext.registerTool recebe name, title opcional, description, inputSchema, execute e annotations opcionais.

Por que aprender:

A forma imperativa atende jornadas que não cabem num formulário ou dependem de lógica e estado ricos.

Conceitos-chave:

nome único · descrição não vazia · execute obrigatório · registro é Promise

O que é:

inputSchema usa JSON Schema para declarar propriedades, tipos, enums, descrições e campos obrigatórios.

Por que aprender:

O schema é parte do raciocínio de escolha e geração de argumentos; validação real ainda deve ocorrer no código.

Conceitos-chave:

type object · propriedades focadas · required coerente · valide no execute

O que é:

O callback execute pode retornar uma Promise; o valor resolvido é entregue ao agente.

Por que aprender:

Resultados pequenos, tipados por convenção e acompanhados de evidência facilitam verificação e encadeamento.

Conceitos-chave:

Promise é aceita · resultado é serializável · UI é atualizada · erros são úteis

O que é:

O signal de registerTool remove a ferramenta quando abortado; o signal recebido por execute cancela a chamada em andamento.

Por que aprender:

Esse modelo evita ferramentas obsoletas e trabalho continuando depois que o agente perdeu interesse.

Conceitos-chave:

signal de registro remove · signal de execução cancela · fetch aceita signal · cleanup é determinístico

O que é:

getTools lista ferramentas expostas ao documento e executeTool executa uma RegisteredTool com entrada estruturada.

Por que aprender:

Essas operações viabilizam agentes in-page e testes controlados sem simular um agente externo.

Conceitos-chave:

getTools é assíncrono · origem pode filtrar · execute usa RegisteredTool · cancelamento opcional

O que é:

Buscar, consultar e verificar disponibilidade formam uma sequência com responsabilidades distintas e sem tool genérica.

Por que aprender:

Um catálogo enxuto melhora a escolha do agente e cria uma base clara para a fase Integrator.

Conceitos-chave:

buscar lista · consultar detalha · disponibilidade verifica · sem sobreposição
