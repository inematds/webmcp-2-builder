Evolua de cliques para ferramentas estruturadas

O que é: Automação visual interpreta pixels e DOM; uma tool expõe intenção, parâmetros e resposta em um contrato explícito.

Por que aprender: A estrutura reduz ambiguidade e torna a execução observável sem eliminar a interface humana.

Conceito aplicado

O contrato deve ser compreensível por quem usa, testável por quem desenvolve e limitado por quem opera. A ferramenta não substitui autorização, validação nem experiência visual.

// Em vez de "clique no terceiro botão"
{
  "tool": "buscar_cursos",
  "arguments": { "tema": "WebMCP", "nivel": "iniciante" }
}

Dica prática

Copie o exemplo, rode primeiro com dados locais e só depois conecte o backend. Mantenha logs sem dados pessoais e provoque pelo menos uma falha.

✓ A entrada inválida produz um erro compreensível.
✓ O efeito aparece na interface para a pessoa.
✓ O caminho manual funciona sem WebMCP.

2

Diferencie API, MCP e WebMCP

O que é: API tradicional é um contrato de rede; MCP padroniza a conversa entre um host e servidores de contexto; WebMCP expõe ferramentas ligadas ao estado da página.

Por que aprender: A fronteira correta evita tratar WebMCP como substituto universal de backend ou de MCP.

✓ Faça

  • ✓ Declare API serve aplicações de forma observável.
  • ✓ Preserve MCP conecta hosts no fluxo manual.
  • ✓ Teste o resultado e o cancelamento.

✗ Evite

  • ✗ Esconder efeitos atrás de descrições vagas.
  • ✗ Confiar na tool como autorização.
  • ✗ Remover o fallback da interface.

Conceito aplicado

O contrato deve ser compreensível por quem usa, testável por quem desenvolve e limitado por quem opera. A ferramenta não substitui autorização, validação nem experiência visual.

MCP → host ⇄ servidor MCP
WebMCP → agente ⇄ documento aberto
MCP + WebMCP → backend e experiência local

O que é: Ferramentas WebMCP acompanham o documento, o usuário autenticado e o estado atual da interface.

Por que aprender: Registrar só o que pode ser usado naquele momento reduz contexto e chamadas inválidas.

3

Verifique a evidência

4

Separe navegador, agente e backend

O que é: O navegador hospeda a tool e a experiência visível; o agente escolhe a ação; o backend continua impondo autorização e regras de negócio.

Por que aprender: Sem essa separação, uma descrição de tool vira uma falsa barreira de segurança.

Decida quando não usar WebMCP

O que é: Nem toda interação precisa virar tool. Conteúdo editorial, navegação simples e ações sem contrato estável podem continuar apenas como Web semântica.

Por que aprender: Recusar uma tool ruim preserva o catálogo, a segurança e a capacidade de escolha do agente.
